# AS-3: Draw the goal-line / ledger boundary

**Status:** pending · **Priority:** low · **Blocked by:** none
**Touches:** `skills/work-cycle/SKILL.md`

## Why

Two involvement mechanisms now coexist and the skill does not say how they
differ:

- a goal's optional `Implementation opinions` line — the user's constraint on
  **one outcome**, authored at scoping;
- `CALIBRATION.md` — the delegated level for a **class of decision**, everywhere,
  learned from accumulated evidence.

`work-cycle` correctly states that implementation opinions are "instructions, not
mere context", but never distinguishes their scope from the ledger's. Left
undrawn, the goal line drifts into carrying per-goal involvement settings
("ask me about dependency choices here"), which is the ledger's job and
re-creates the per-item involvement field the 2026-08-29 session deliberately
rejected.

## Acceptance criteria

1. One short passage states the boundary: **the goal line constrains this
   outcome; the ledger governs classes of decision everywhere.**
2. It says explicitly that a goal line is not the place to set an involvement
   level for a decision class.
3. No new mechanism is introduced — this is drafting, not design.

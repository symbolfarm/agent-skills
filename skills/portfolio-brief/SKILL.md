# Portfolio brief

Read the portfolio's `WORKFLOW.md`, `QUEUE.json`, recent evidence and worker
results. Historical goals/tasks are not backlog. Use the same queue helper and
lane/capability filters as the worker when stating what it can select next.

Lead with meaningful changes in understanding or capability. Link new digests
with enough context to explain why they matter. Distinguish completed work from
partial progress, failed runs and an intentionally empty queue.

Surface consequential blockers, including what decision is needed and why.
Batch routine progress; do not turn every execution record into a human report.
A concise account with no decision needed is a successful brief. Do not generate
replacement work simply because the queue is empty.

Report what happens next under existing authorization. A recommendation is
allowed if labelled; only the user authorizes new direction or charter activation.
Do not re-rank, execute work or mutate scheduler jobs while producing a brief.

Reconcile completion claims with primary artifacts. A report repeating another
report is not verification. Treat scheduler configuration and live execution as
separate facts: a repository update does not prove an installed worker changed.

Use the current conversation or an already authorized delivery channel. Preserve
existing delivery and continuation settings unless the user requests a change.
Replies are ordinary conversation; do not require a special phrase to steer work.
